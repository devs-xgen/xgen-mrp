# P6.1: System Settings & Configuration

**Priority:** 6 (Medium - System Configuration)
**Estimated Effort:** Large (5-7 days)
**Status:** Not Started
**Category:** System Management

---

## Overview

Implement comprehensive system-wide settings and configuration management for the XGen MRP platform. This includes email templates, notification configurations, backup settings, API key management, feature flags, and global system parameters that affect all organizations.

## Business Value

- **Centralized Configuration:** Single source of truth for all system settings
- **Operational Efficiency:** Configure system behavior without code changes
- **Email Customization:** Branded communication with customizable templates
- **Feature Control:** Enable/disable features globally via feature flags
- **Security Management:** Centralized API key and integration management
- **Compliance:** Audit all configuration changes

## User Stories

### Story 1: Global System Settings
**As a** SuperAdmin
**I want to** configure global system settings (timeouts, limits, defaults)
**So that** I can optimize system behavior and resource usage

**Acceptance Criteria:**
- Configure session timeout duration
- Set API rate limiting parameters
- Configure database connection pool settings
- Set file upload size limits
- Configure pagination defaults
- Set default currency and locale
- Configure maintenance mode
- Audit all setting changes

### Story 2: Email Template Management
**As a** SuperAdmin
**I want to** create and manage email templates for all system notifications
**So that** emails are branded and consistent across all communications

**Acceptance Criteria:**
- Create/edit email templates with variables
- Preview templates before saving
- Support HTML and plain text formats
- Built-in templates for common scenarios:
  - User invitation
  - Password reset
  - Order notifications
  - Production alerts
  - Delivery confirmations
  - Billing reminders
- Use template variables ({{userName}}, {{orderNumber}}, etc.)
- Test send emails
- Version history for templates

### Story 3: Notification Configuration
**As a** SuperAdmin
**I want to** configure notification rules and channels
**So that** users receive timely alerts through their preferred channels

**Acceptance Criteria:**
- Configure notification channels (email, SMS, Slack, webhook)
- Set notification rules by event type
- Configure recipient groups
- Set notification priorities
- Configure rate limiting (prevent spam)
- Enable/disable notifications by category
- Test notification delivery
- View notification delivery logs

### Story 4: Backup Configuration
**As a** SuperAdmin
**I want to** configure automated database backups
**So that** data is protected and recoverable

**Acceptance Criteria:**
- Configure backup schedule (daily, weekly)
- Set backup retention policy
- Configure backup storage location
- Enable/disable automated backups
- Manual backup trigger
- View backup history
- Restore from backup (with confirmation)
- Backup size and health monitoring

### Story 5: API Key Management
**As a** SuperAdmin
**I want to** manage API keys for external integrations
**So that** third-party systems can securely access our APIs

**Acceptance Criteria:**
- Generate API keys with permissions
- Set key expiration dates
- Revoke keys immediately
- View key usage statistics
- Configure rate limits per key
- Label keys by integration/purpose
- Log all API key operations
- Rotate keys with overlap period

### Story 6: Feature Flags
**As a** SuperAdmin
**I want to** enable/disable features globally via feature flags
**So that** I can control feature rollout and disable problematic features

**Acceptance Criteria:**
- List all available feature flags
- Enable/disable features globally
- Enable features for specific organizations
- Rollout percentage (e.g., enable for 10% of users)
- View feature usage statistics
- Schedule feature activation (future date)
- Audit all feature flag changes

## Technical Specifications

### Database Schema

**New Models:**

```prisma
model SystemSetting {
  id          String   @id @default(cuid())
  category    String   // "general", "email", "notification", "backup", "api"
  key         String   @unique
  value       Json     // Flexible value storage
  dataType    String   // "string", "number", "boolean", "json"
  description String?
  isPublic    Boolean  @default(false) // Can non-admin read?
  updatedBy   String
  updatedAt   DateTime @updatedAt
  createdAt   DateTime @default(now())

  updater     User     @relation(fields: [updatedBy], references: [id])

  @@index([category])
  @@index([key])
}

model EmailTemplate {
  id          String   @id @default(cuid())
  name        String   @unique
  subject     String
  bodyHtml    String   @db.Text
  bodyText    String?  @db.Text
  category    String   // "auth", "order", "production", "billing", "delivery"
  variables   String[] // ["userName", "orderNumber", "dueDate"]
  isDefault   Boolean  @default(false)
  isActive    Boolean  @default(true)
  version     Int      @default(1)
  createdBy   String
  updatedBy   String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  creator     User     @relation("CreatedTemplates", fields: [createdBy], references: [id])
  updater     User     @relation("UpdatedTemplates", fields: [updatedBy], references: [id])

  @@index([category])
  @@index([isActive])
}

model NotificationRule {
  id          String   @id @default(cuid())
  name        String
  eventType   String   // "ORDER_CREATED", "PRODUCTION_DELAYED", etc.
  channels    String[] // ["email", "sms", "slack", "webhook"]
  recipients  Json     // Flexible recipient configuration
  priority    String   @default("NORMAL") // "LOW", "NORMAL", "HIGH", "URGENT"
  isEnabled   Boolean  @default(true)
  rateLimit   Int?     // Max notifications per hour
  template    String?  // Email template name
  webhookUrl  String?
  createdBy   String
  updatedBy   String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  creator     User     @relation("CreatedRules", fields: [createdBy], references: [id])
  updater     User     @relation("UpdatedRules", fields: [updatedBy], references: [id])

  @@index([eventType])
  @@index([isEnabled])
}

model ApiKey {
  id          String    @id @default(cuid())
  name        String
  key         String    @unique
  keyHash     String    // Store hashed key for security
  permissions Json      // Flexible permission structure
  rateLimit   Int       @default(1000) // Requests per hour
  expiresAt   DateTime?
  lastUsedAt  DateTime?
  isActive    Boolean   @default(true)
  createdBy   String
  createdAt   DateTime  @default(now())

  creator     User      @relation("CreatedApiKeys", fields: [createdBy], references: [id])

  @@index([keyHash])
  @@index([isActive])
  @@index([expiresAt])
}

model FeatureFlag {
  id              String   @id @default(cuid())
  name            String   @unique
  description     String?
  isEnabled       Boolean  @default(false)
  rolloutPercent  Int      @default(100) // 0-100
  organizations   String[] // Specific orgs to enable for
  scheduledAt     DateTime?
  updatedBy       String
  updatedAt       DateTime @updatedAt
  createdAt       DateTime @default(now())

  updater         User     @relation(fields: [updatedBy], references: [id])

  @@index([name])
  @@index([isEnabled])
}

model BackupHistory {
  id          String   @id @default(cuid())
  fileName    String
  fileSize    Int      // Bytes
  location    String   // Storage path
  status      String   // "COMPLETED", "FAILED", "IN_PROGRESS"
  startedAt   DateTime
  completedAt DateTime?
  error       String?  @db.Text
  triggeredBy String?  // User ID or "AUTOMATIC"

  @@index([status])
  @@index([startedAt])
}
```

## Testing Scenarios

### Email Templates
1. Create template with variables → Success
2. Preview with sample data → Renders correctly
3. Send test email → Email received
4. Update template → Version incremented
5. Use template in notification → Variables replaced

### API Keys
1. Generate key → Shown once, then hidden
2. Use key for API request → Authenticated
3. Exceed rate limit → 429 error
4. Use expired key → 401 error
5. Revoke key → Immediately invalidated

### Feature Flags
1. Enable feature globally → All users see it
2. Set 50% rollout → ~50% of users see it
3. Target specific org → Only that org sees it
4. Disable feature → No users see it

## Dependencies

## Security Considerations

- Encrypt sensitive settings (API keys, passwords)
- Validate all setting changes
- Prevent SQL injection in backup restore
- Rate limit API key generation
- Audit all configuration changes
- Restrict access to SUPER_ADMIN only
- Validate email templates (prevent XSS)
- Sanitize notification inputs
