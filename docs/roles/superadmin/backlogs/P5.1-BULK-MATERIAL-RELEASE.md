# P5.1: Bulk Material Release

**Priority:** 5 (High - Missing Core Feature)
**Estimated Effort:** Medium (2-3 days)
**Status:** Not Started
**Category:** Material Management

---

## Overview

Enable SuperAdmin to bulk release material reservations across multiple production orders or materials in a single operation. This is critical for emergency scenarios where multiple orders need to be cancelled or materials need to be freed up quickly.

## Business Value

- **Emergency Recovery:** Quickly free up materials when orders are cancelled in bulk
- **Resource Reallocation:** Enable rapid material reallocation during production emergencies
- **Efficiency:** Reduce time from hours to minutes when releasing dozens of reservations
- **Audit Trail:** Maintain comprehensive audit logs for bulk material operations

## User Stories

### Story 1: Bulk Release by Production Order
**As a** SuperAdmin
**I want to** select multiple production orders and release all their material reservations
**So that** I can quickly free up materials when orders are cancelled or need to be reset

**Acceptance Criteria:**
- Select multiple production orders (10+ at once)
- Preview total materials and quantities to be released
- Require audit reason (min 15 characters)
- Release all reservations atomically (transaction)
- Update material stock levels correctly
- Create activity logs for each release
- Show success/failure summary after operation

### Story 2: Bulk Release by Material
**As a** SuperAdmin
**I want to** select a material and release all pending reservations for it
**So that** I can free up critical materials that are over-reserved

**Acceptance Criteria:**
- View all reservations for a specific material
- Filter by production order status, date range, quantity
- Select specific reservations or "Release All"
- Preview impact on production orders
- Require audit reason
- Atomic transaction for all releases
- Notify affected stakeholders (future enhancement)

### Story 3: Conditional Bulk Release
**As a** SuperAdmin
**I want to** bulk release reservations based on filters (date, status, quantity)
**So that** I can target specific scenarios (e.g., all overdue orders, all suspended orders)

**Acceptance Criteria:**
- Filter reservations by:
  - Production order status (PENDING, CANCELLED, ON_HOLD)
  - Date range (created before X date)
  - Material type or category
  - Quantity thresholds
- Preview filtered reservations before release
- Bulk release with single audit reason
- Transaction safety with rollback on failure

## Technical Specifications

### Database Operations

**New Server Actions** (`src/lib/actions/superadmin/materials/bulk-release.ts`):

```typescript
// Bulk release by production orders
export async function bulkReleaseMaterialReservationsByOrders(
  orderIds: string[],
  reason: string
): Promise<ActionResult<BulkReleaseResult>>

// Bulk release by material
export async function bulkReleaseMaterialReservationsByMaterial(
  materialId: string,
  filters: ReservationFilters,
  reason: string
): Promise<ActionResult<BulkReleaseResult>>

// Conditional bulk release
export async function bulkReleaseMaterialReservationsConditional(
  filters: ConditionalFilters,
  reason: string
): Promise<ActionResult<BulkReleaseResult>>

interface BulkReleaseResult {
  totalReservations: number;
  successCount: number;
  failedCount: number;
  failedReservations: Array<{
    reservationId: string;
    error: string;
  }>;
  releasedQuantityByMaterial: Record<string, number>;
}
```

## Testing Scenarios

### Happy Path
1. Select 20 production orders
2. Preview shows 150 material reservations
3. Enter reason "Bulk order cancellation due to client request"
4. All 150 reservations released successfully
5. Material stock updated correctly
6. Activity logs created

### Error Scenarios
1. Network failure mid-transaction → Full rollback
2. Insufficient permissions → Blocked with error
3. Reservation already consumed → Skip with warning
4. Invalid order IDs → Clear error message
5. Empty audit reason → Validation error

### Edge Cases
1. 0 reservations to release → Inform user, no operation
2. 1000+ reservations → Batch processing with progress
3. Material deleted during operation → Graceful failure
4. Concurrent release attempts → Proper locking
